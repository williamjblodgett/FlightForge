## P1 — fix before broader launch

### 1. Configured production authentication hostname does not resolve

**Evidence:** Both operating-system DNS and an independent public DNS query failed for `hpdkfgidjqqkejhyzbgf.supabase.co`. Public DNS returned status 3 (NXDOMAIN), zero answers; `/auth/v1/health` could not be reached. This confirms a hostname/configuration availability problem, not whether the project was paused, removed, or mistyped.

**Impact:** New hosted signup, Supabase sign-in and recovery cannot reliably complete. Existing local-account fallback may still work. Google sign-in cannot be activated successfully against this endpoint.

**Related monitoring gap:** `/api/health` returned 200/`ok` and `supabaseConfigured:true`; `app/api/health/route.ts` checks configuration presence, not authentication-provider availability. Database/schema/storage checks did pass.

**Fix:** Check the Supabase dashboard, restore/confirm the intended project and correct runtime URL/key together. Add a separately reported, cached external-auth availability check and alert. Test actual email delivery and an actual hosted login before declaring it ready.

### 2. A hosted password reset leaves the old local password and sessions valid

**Locations:** `modules/auth/account-repository.ts:418`, `:490`, `:654`; `app/api/auth/login/route.ts:81`; `app/api/auth/update-password/route.ts:51`.

**Reproduction:** Using real repository/password code and isolated SQLite, create a local account/session, link its verified Supabase identity, and run the actual update-password route with a valid recovery intent and controlled provider. The route returns 200 and changes the provider password; the original local password and original local session still authenticate.

**Cause:** Linking retains local password hashes/sessions. When Supabase rejects a password, login still falls back to the old local credentials, even for linked accounts. Hosted recovery only updates Supabase.

**Fix:** Atomically retire local credentials and sessions when linking succeeds; prohibit local authentication/session lookup for linked accounts. Backfill retirement for previously linked accounts without breaking unlinked legacy accounts. Cover migration → reset → rejection of old password/session in integration tests.

### 3. Expired private coaching videos can escape deletion permanently

**Location:** `modules/media-analysis/coaching-repository.ts:87`.

**Reproduction:** An expired upload exists; object-storage deletion fails during coaching-history access. The actual repository marks the database row deleted anyway. A subsequent scheduled purge selects no work. Isolated result: row deleted, object still present, one delete attempt; scheduled result `{deleted:0,failed:0}`.

**Impact:** Private media can remain stored beyond the stated expiry and no longer be eligible for retry. This is a reproducible retention defect, not evidence that existing production videos have leaked.

**Fix:** Mark completion only after successful storage deletion. Preserve retryable state, log/alert failures, and reconcile previously marked records whose objects may remain. Test retry after transient storage failure.

## P2 — correctness, safety and usability

### 4. Password recovery claims a link was sent when the provider failed

**Locations:** `app/api/auth/reset-password/route.ts:24`; `app/forgot-password/ForgotPasswordForm.tsx:20`.

**Reproduction:** Run the actual route with a provider transport-error response. It still returns 200 `{accepted:true}`, making the UI display that a recovery link is on its way.

**Fix:** Preserve account-enumeration protection while returning the same retryable outage message for transport/service failures. Cover SMTP failure, throttling, and unavailable-provider cases.

### 5. Approving a course claim does not update public ownership status

**Locations:** `modules/courses/course-repository.ts:413`; `modules/courses/demo-courses.ts:8`; `app/courses/[slug]/page.tsx:154`; `app/api/claims/route.ts:54`.

**Evidence:** Approval writes `VERIFIED` to the database, while course detail, claim page and submission validation read the static catalog whose builders set `UNCLAIMED`. The public notice/claim action therefore remain, and another applicant can pass the already-claimed check. This was source-confirmed; no real course claim was approved during testing.

**Fix:** Read authoritative ownership state from the database for display and mutation validation. Add an approval-to-public-page integration test, including rejection of a second claim.

### 6. Event times use the coordinator's device zone instead of the selected event zone

**Location:** `components/events/EventPublisherForm.tsx:210` (serialization), `:215` (editing).

**Reproduction:** Device in Los Angeles; event zone Eastern; enter October 10, 2026 at 9:00 AM. The current helper stores `16:00Z`, which displays as **12:00 PM Eastern**, three hours late. Editing has the same device-zone assumption.

**Fix:** Convert local date/time using the selected IANA zone in both directions. Test different device/event zones plus daylight-saving ambiguous/nonexistent times.

### 7. Blocked users' messages remain visible in public-channel previews

**Locations:** `modules/community/community-repository.ts:815`; `components/community/CommunityHub.tsx:267`.

**Reproduction:** In isolated migrated SQLite, a viewer blocks the author of a channel's latest message. Channel summaries still return the full message and author's name, and the UI renders them. The full transcript correctly filters blocked authors, so previews contradict it.

**Fix:** Apply the same block policy to latest-message previews, author metadata and unread calculations. Test blocks in both directions.

### 8. Older conversations become inaccessible because lookup uses capped lists

**Location:** `modules/community/community-repository.ts:839`.

**Reproduction:** An existing public channel has active membership and 100 newer channels. The real lookup returns 404, because it searches only the newest 100 public channels. Private conversations have the analogous 50-item limit.

**Fix:** Fetch a conversation directly by ID with membership/block authorization. Keep list pagination independent from existence/authorization. Test older channels and direct conversations beyond both thresholds.

### 9. Offline draft recovery dismisses its warning but leaves scoring disabled

**Locations:** `components/rounds/LiveRoundScorecard.tsx:253`, `:472`.

**Reproduction:** Keep an old event-round draft on one device, finish that round elsewhere, revisit, and choose “I saved my backup — use the current round.” A real React/JSDOM probe showed the warning disappear while controls stayed disabled and status remained “Restoring this round from this device…”. The page simultaneously says the current round is ready. A reload is required.

**Fix:** Update sync state, last-sync metadata and relevant references when adopting the current round. Test both preservation of the old backup and immediate editability of the new round.

### 10. Concurrent caddie feedback loses a learned sample

**Location:** `modules/bags/bag-repository.ts:603`.

**Reproduction:** Submit feedback for two different recommendations for the same disc/throw type concurrently. Both observations are saved, but the profile calculation reads before its transaction and overwrites the other's aggregate. Actual isolated result for 100-ft and 300-ft samples: `sample_count:1`, typical distance `300`, instead of two samples averaging 200.

**Fix:** Aggregate committed observations atomically or use optimistic-lock retries. Add a two-request concurrency regression test.

### 11. Blank optional distances distort caddie averages

**Location:** `modules/bags/bag-repository.ts:720`.

**Reproduction:** Sequential feedback contains measured distances 100, blank, 300. The actual profile calculation returns **166.67 ft**, rather than **200 ft** for the two measured throws. The denominator counts feedback entries that contained no distance.

**Fix:** Track measured-distance count independently or calculate the mean over non-null measurements. Test mixed measured/unmeasured feedback and backfill existing profiles.
