# September 28 QA repairs

Scope: the eleven findings in `QA-REVIEW-2026-09-28.md`. Ten application defects are repaired. The remaining external Supabase availability problem needs project-owner action; monitoring and failure handling for it are implemented.

## Changes

| Finding | Implementation |
| --- | --- |
| Auth availability | Cached, deduplicated, three-second provider probe; degraded health reports 503; signup pauses and sign-in explains an outage. Existing unlinked local accounts remain available. |
| Linked legacy credentials | Atomic credential retirement and session revocation at identity linking; fail-closed legacy authentication/session guards; bounded historical cleanup through schema startup, scheduled execution, and request-driven maintenance. |
| Coaching retention | Shared storage-first deletion with durable confirmation; transient storage/database failures stay retryable; historical false tombstones are reconciled; repeated confirmed deletes succeed. History, explicit deletion, admin purge, scheduled worker, and bounded traffic-driven sweeps use this logic. |
| Recovery errors | Inspect provider-returned errors, handle network/SMTP failures, preserve recipient privacy, distinguish request throttling, and avoid promising delivery. |
| Course ownership | Server overlay uses persisted verified ownership on details, claim forms, paginated discovery, and favorites, including catalog-only courses. Transactional guards prevent stale/competing approvals and new applications after approval; grants/audits roll back together. Review requests now require an application version. |
| Event time zones | Form serialization and editing use the selected IANA zone, not the device zone. Reject nonexistent/repeated newly entered DST times with a clear error; preserve an unchanged existing instant during editing. |
| Blocked previews | Apply two-way blocking and deletion rules to every preview field and unread count. |
| Older conversations | Targeted authorized lookup is independent of inbox limits; transcript responses include the selected conversation for its header/composer. |
| Offline draft recovery | Reset round identity/version, synchronization state, conflicts, finish mutation and current hole when the user acknowledges backing up an old draft. Scoring becomes immediately usable. |
| Concurrent feedback | Compute counts, distance averages and success rates within the observation transaction; SQL updates tuning against the current profile; return the profile from that same transaction. |
| Missing distances | Only supplied distances contribute to the mean. Reconcile historical count/distance/success errors from durable observations. |

Additional security repair: password changes compare the credential snapshot they verified. A stale request cannot overwrite a newer password or revoke its sessions/record a false success audit.

No database schema changes or credential/configuration changes are required for these repairs. The existing 19 D1 migrations supply all required tables and transaction guards. Historical repair is bounded operational work, not data embedded in schema migrations. Account links intentionally invalidate old local sessions; do not restore those credentials during rollback.
