# FlightForge — mobile and round-reliability release

Release scope: implementation of the September 10 Astra review. This is an upgrade to the existing public Sites application, not a Supabase cutover or a declaration that the entire master product specification is production-complete.

## Implemented journeys

- Compact Home/Explore/Play/Events/More navigation, form-first mobile account pages, primary course actions near the top, consistent active navigation, visible sign-out, and contextual Bag/Coach access.
- Discover by bookmarkable filters and pagination; open a full-screen map drawer; pan, zoom, select clusters and course previews; search the visible area; return with Escape and restored focus. Map summaries cover the full matching catalog, independently of the 24-item list page.
- Favorite from a filtered result, authenticate through required account steps, and resume the same safe URL with an explicit idempotent save intent.
- Start a private personal round at a real listed course, select a published layout or a clearly labeled strokes-only card, record aces/high scores/penalties, resume the active hole, finish, refresh a stable result URL, reopen history, and make reasoned audited personal-score corrections.
- Preserve actual layout/hole/par versions in immutable round context. Unknown pars and distances are not invented. Fictional demonstration rounds remain labeled separately.
- Save local scores with an IndexedDB/localStorage journal and memory-only fallback warnings, export/retry actions, explicit conflict choice, bounded background sync retries, and reauthentication recovery. Import guest scores only by explicit choice; keep the guest draft until synchronization succeeds.
- Pass authorized current-round context to text and voice caddie requests; return from Bag or Coach to the active hole. The server rechecks ownership and discloses missing shot inputs. Voice has keyboard talk controls, disconnect, timeouts, and microphone cleanup.
- Fieldwork opens with Measure/Find Space. Capture a draft, correct the same throw, save explicitly, tag disc/throw/session, and deliberately transfer a saved distance estimate to Coach without discarding GPS uncertainty or automatically changing bag calibration.
- Coach retains clip/answers after failed upload, supports cancellation and idempotent retry, reports history failures honestly, confirms in-app departure with an unsaved clip, and retains delete dialogs with recoverable errors.
- Auth preserves full safe destinations through verification, onboarding, first-password setup, hosted linking, and recovery. Sensitive player APIs reject incomplete or unverified accounts. Hosted linking rejects suspended accounts and unverified-email account adoption.
- Verification resend and a durable legacy-email delivery outbox use bounded retries and leases. Account creation and delivery enqueue are atomic. Only hashed verification tokens are persisted. Unread-message polling uses a private count query, not the full community dashboard.

## Architecture and schema

The deployed application remains a TypeScript React/Vinext modular monolith on a Cloudflare Worker, with Sites D1 for application records and private R2 media. Supabase identity integration and PostgreSQL/PostGIS foundations remain separate from the runtime repository cutover.

The standard Sites build wrapper encountered a Windows npm-shim resolution error; the same repository build script was run directly and validated before packaging.

Additive D1 migrations 0013 and 0014 introduce round session/context fields and the verification delivery outbox. Existing round, score, account, and audit records are not deleted or rewritten. Apply through the tracked migration ledger before serving new code; do not manually replay the SQL. All 15 migrations apply successfully to a fresh SQLite/D1 test database (144 tables).

Key modules: modules/rounds, modules/auth, modules/notifications, modules/courses, modules/community, modules/fieldwork, and modules/media-analysis. New routes include /more, /rounds/new, /rounds, /rounds/[id], /api/rounds/personal, /api/rounds/[id], /api/auth/resend-verification, and /api/community/unread. app/player-ui.css layers compact utility layouts over the existing brand instead of replacing course artwork with fictional imagery.

## Runtime configuration and operations

No new paid provider is required for the core discovery/scoring changes. Preserve existing Sites DB and MEDIA bindings and runtime secrets. RELEASE_ID is exposed in health responses; /api/health now checks required round, layout, video, and outbox schema without exposing credentials.

Legacy verification delivery uses EMAIL_DELIVERY_MODE plus EMAIL_VERIFICATION_WEBHOOK_URL and EMAIL_VERIFICATION_WEBHOOK_SECRET when webhook delivery is selected. Support/privacy contacts and current legal-version configuration still gate public registration. Raw keys must remain server-side; never enter them in source or chat.

The outbox is swept opportunistically using waitUntil, at most once per minute per active Worker instance, and by the existing scheduled handler if the host supplies a scheduled trigger. At most five due jobs are claimed per sweep with per-job leases; retries stop after six attempts. There is no promise of one-minute delivery with no site traffic. A production scheduler/alert owner must configure and verify the schedule and monitor failed jobs. Delivery is at least once, not exactly once; valid older verification links remain usable until expiry.

Deployment rollback should select the previous known-good Sites version, preserve the additive schema, and verify health plus a dedicated signed-in journey. Do not run destructive down migrations against live user data. A real production backup/restore rehearsal remains a launch gate.

## Explicit limitations and follow-up work

- Real inbox delivery/recovery, hosted OAuth/MFA, live voice/provider billing and microphone tests were not exercised. Existing integrations retain configuration and account-approval dependencies; core scoring does not depend on AI.
- Physical iPhone/Android GPS/camera, keyboard safe areas, 200% text enlargement, all widths/orientations, and measured field performance remain a device test matrix. WebKit automation is not a physical iPhone test. GPS estimates are not laser/depth measurements.
- Practice handoff to Coach is implemented; linking those samples into a specific owned-disc calibration/feedback record remains a separate explicit-consent flow. Fieldwork retains the most recent 20 local summaries. Practice permission and a new authoritative practice-space dataset are not implied by nearby course listings.
- Personal rounds require sign-in. Guest scoring remains available for event/demo cards. Event-result corrections require organizer review; there is no new self-service event-correction tool.
- The map is an interactive provider-neutral location overview, not licensed Google satellite tiles or navigation-grade surveying. Existing operator-source attribution and access disclaimers remain. No new statewide data audit or licensed photography acquisition was performed here.
- Supabase data cutover, live booking/payment inventory, Stripe reconciliation, full persisted import approvals/rollback, third-party malware scanning/transcoding, production media-retention scheduling, coach-reviewed AI benchmarks, and independent legal/security approval are not completed by this release.
- Real-user latency/Web Vitals, a full screenshot-regression baseline, live owner/admin/media moderation end-to-end exercises, and production restore/rollback drills still need operational validation. This release adds focused journey/failure tests, not exhaustive verification of every master-plan feature.

Recommended next slice: a dedicated staging acceptance run with configured email and media providers, purpose-created owner/player accounts, physical iPhone/Android devices, and backup/restore rehearsal before activating more public uploads or payments.
